# Blog reconstruction workflow

## 优先级与模式

冲突时按以下顺序处理：

`用户任务 > 事实准确 > 信息完整 > Token 效率 > 文风`

默认使用 `economy`：原文只完整输入一次，首遍同时生成知识锚点与证据胶囊，后续只定向回查有风险的局部。用户明确要求最高保真，或高风险内容无法通过局部回查确认时，才使用 `maximum-fidelity`；即使如此，也先尝试定向回查。

## 双重切片

从 `metadata.duration_seconds` 取得总时长，并估算转录文本的 Token 数：

优先使用当前模型的真实 tokenizer。运行时没有 tokenizer 时，按文本类型做保守估算并倾向多切一片，不使用过于乐观的字符换算。单片 Token 预算不得超过可用上下文的三分之一，以便给固定前缀、证据胶囊和模型输出留出空间；用户给出更低预算时使用更低值。

```text
时长分片数 = ceil(总时长秒数 / 3600)
Token 分片数 = ceil(预估 Token / 单片 Token 预算)
最终分片数 = max(1, 时长分片数, Token 分片数)
每片目标时长 = 总时长秒数 / 最终分片数
```

只有总时长大于 1 小时时，时长规则才产生多个片段；恰好 1 小时不因时长切片。70 分钟应得到两个约 35 分钟片段。不到 1 小时但文本过密时，Token 预算仍可产生更多片段。

这是上下文控制切片，不是主题切片。优先按 ASR 时间比例定位；没有可用句子时间时，按文本长度比例生硬等分。允许把切点移动到很近的句末，但不得因此让任何片段超过 1 小时或单片 Token 预算。各片不重叠并恰好覆盖原文一次。

每片复用完全相同的固定处理前缀，以便保持标准并利用可能的提示词缓存。前缀只定义角色、提取目标、紧凑格式、事实边界和禁止事项；片段编号、范围与正文作为变量放在前缀之后。

## 知识锚点与证据胶囊

每个片段只完整阅读一次，并按原文先后顺序生成紧凑记录：

```text
K023｜步骤｜配置环境变量后重新启动服务
细节：变量名、配置位置、执行顺序、必要条件
来源：片段2/段落18-21｜回查：否
```

每条记录包含：

- 全局唯一且递增的锚点编号；
- 类型：观点、概念、步骤、案例、条件、风险或结论；
- 严格一句话的知识点；
- 写作确实需要的最小细节，如因果、参数、步骤、限制或案例背景；
- 片段和原文段落位置；
- `回查：是/否`。

没有内容的字段不输出。知识点负责防遗漏，证据胶囊负责避免写作时再次输入整段原文。不要在这一阶段写博客、制造过渡语或压缩掉独立的条件、例外和案例。

片段完成后按编号拼接记录。只合并语义和证据都相同的重复项；重复表述带有新参数、条件、例外或案例时，保留新增信息。原始时间顺序是默认叙事顺序，只有为了读者理解必须调整时才重排，并保持步骤依赖不变。

## 按需回查

只有出现以下可观察条件时，标记 `回查：是`：

- 专有名词、数字、命令、代码、参数或版本不完整；
- 步骤依赖断裂，或跨片内容冲突；
- 案例缺少理解结论所必需的背景；
- 证据胶囊不足以支撑锚点，或属于低置信度提取；
- 涉及可能变化或高风险的信息，需要核对原文或权威来源。

按来源位置读取最小必要范围，通常是目标段落及相邻段落。不得重新输入完整转录，也不得因为“可能更稳妥”而回查所有锚点。需要联网核实时只使用完成核对所需的一手资料，并区分讲者观点、外部事实和编辑推断。

## 博客重构

仅使用合并后的锚点、证据胶囊和定向回查结果规划文章。标题和层级服从内容，不套用固定的“背景—定义—总结”模板。

文章应像懂行的朋友在深入浅出地解释：先让读者知道正在解决什么问题，再自然展开概念、原因、步骤、案例和边界。合理使用 H2/H3、加粗、引用块和列表；操作流程使用有序列表。合并口语重复和无信息量过渡，但保留事实、先后关系、重要例子、限制和讲者明确表达的观点。

不得虚构作者立场，不得虚构经历，不得虚构数据，不得虚构代码、案例、引用或执行结果。讲者观点应保持为观点；无法确认的技术细节应弱化表述或标记待核对，不能写成确定事实。

## 覆盖检查

起草时可临时把来源锚点写成不可见标记，例如 `<!-- K023 -->`。完成草稿后执行机械检查：

1. 每个锚点至少出现一次，且没有未知编号。
2. 合并后的同一锚点只覆盖一次；依赖步骤顺序正确。
3. 正文中的关键事实都能对应锚点或定向核对结果。
4. 删除所有锚点标记后，重新检查文章连贯性。

这项检查使用压缩材料和草稿，不重新读取全文。

## 纯净发布

首行严格使用以下一种格式：

```markdown
# 《视频或播客名称》
# 《视频或播客名称 第X集/期》
```

标题之后直接进入正文。最终 Markdown 不包含开场寒暄、执行过程、切片说明、知识清单、锚点、时间戳、日志、质量评分或总结性废话。

先把草稿写到最终目录中的同级临时文件。确认正文非空、标题合规、锚点覆盖完成、内部标记清零后，再原子发布为未占用的 `*.blog.md`。成功发布之后才清理本次运行的私有暂存目录；最终博客之外不保留切片、胶囊、转录文件、ASR 响应或草稿。
