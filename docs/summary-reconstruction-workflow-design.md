# 中文总结重构工作流设计

## 目标

VidScribe 将口语化、冗长的视频或播客转录重构为一篇逻辑清晰、自然易读的中文 Markdown 总结。最终文件根据实际内容使用中文标题和 `.summary.md` 后缀；完整成功时，本次运行只新增这一份总结并清除自己的私有暂存材料，输出目录中的既有文件保持不变。失败时保留私有暂存目录，以便恢复且不误删用户输入。

## 架构边界

Python CLI 继续负责媒体探测、音频准备、Paraformer 转录、三类转录工件持久化和运行创建媒体的安全清理。它不调用通用大模型。

Agent Skill 把 CLI 输出放入 `.video-to-summary-stage-<随机值>`，完成分片、逐窗保真注记、总结重构、必要的中文翻译、覆盖检查、内容标题生成和原子发布。最终总结验证成功后，才清理该暂存目录中的转录和重构中间产物。

## Token 成本模型

旧式两遍工作流至少需要一次全文提取和一次全文回查，输入成本接近 `2T + 输出`。保真成稿把成本调整为：

```text
一次全文提取 T（产出逐窗保真注记 N）+ 少量定向回查 R + 输出
```

`N` 近乎无损：只剔除口癖、重复与无信息过渡，保留实体、数字、参数、步骤、命名与例子等一切可溯源信息。它不做旧式「观点化 / 一句话压缩」——那正是信息丢失的根源，也是从旧 economy 契约切到保真注记的原因。`R` 只覆盖有明确风险的节点。固定片段前缀保持一致，并允许底层模型利用提示词缓存。

Token 数优先由当前模型的 tokenizer 计算；没有 tokenizer 时采用保守估算。单片预算最多使用可用上下文的三分之一，为指令、注记材料和输出预留空间。

## 双重切片

```text
时长分片数 = ceil(duration_seconds / 3600)
Token 分片数 = ceil(estimated_tokens / token_budget)
最终分片数 = max(1, 时长分片数, Token 分片数)
```

70 分钟得到两个 35 分钟片段；密度很高但不足一小时的文本仍可能因 Token 预算增加片数。片段按时间或文本比例生硬等分，不重叠且覆盖原文一次。

## 单次提取（逐窗保真注记）

每个片段只完整阅读一次，并按原文顺序产出近乎无损的**保真注记**条目，每条包含：

- 全局唯一且递增的编号与主题标签（概括本窗讲什么，供合并与取用，不替代证据）；
- 各信息槽：命名实体 / 标识符、要点、步骤、数字与单位、示例、对比取舍、坑与修法、讲者强调——凡该片段出现的都保留原词与顺序；
- 片段与段落位置；
- 是否需要回查（命名或数字拿不准时标记「待回查」）。

保真注记不写总结、不造过渡语，不把独立的条件、例外或案例压缩掉；不对信息做「观点化」或「一句话压缩」。跨片合并只删除语义与证据都相同的真正重复项。

## 按需回查、中文化与写作

只有专有名词或参数缺失、步骤断裂、冲突、案例背景不足、低置信度或高风险信息才回查来源附近的最小范围。正常情况下不得再次输入完整转录。

成稿以保真注记与定向回查结果为写作输入，结构服从内容；每个内容单元（通常一个 H2）走「一轮成稿 + 一轮质检」，不机械三轮重写，整篇不设字数上限。临时注记编号用于逐项对账每个知识点、实体与步骤都得到覆盖且顺序正确，发布前全部移除。主要为英文或其他非中文语言时，在事实与结构核对后执行完整中文翻译与润色，再用注记逐项检查翻译没有遗漏条件、例外或案例。最后的文风检查只读取成稿。

## 内容标题与文件名

最终标题只能在理解完整内容后生成，应以简洁中文概括核心议题或结论，不能从下载 stem、哈希或 `source-*` ID 机械派生。清理文件系统非法字符后形成唯一语义标题，同一值用于首行 `# 《语义标题》` 和文件名 `语义标题.summary.md`；实际追加的避碰序号单独登记，重名时追加 `-2`、`-3`。避碰后缀不属于语义标题，首行保持不变。

## 持久化恢复清单

私有暂存目录内的 `.run-manifest.json` 以原子写入方式记录 schema 版本、运行 ID、解析后的目录、所有运行创建文件的精确路径、语义标题、避碰序号、目标路径、暂存目录内发布候选路径、候选文件的稳定实体身份、正文哈希和单向状态机。先登记尚未创建的候选路径、目标和哈希，再在暂存目录 exclusive-create 候选；取得实体身份后才进入发布准备状态。任何最终目录写入、发布或清理前先更新清单；清单和空暂存目录最后删除。

恢复时重新验证清单、运行 ID、路径归属、稳定文件实体身份和正文哈希。只有设备/inode 或卷/file ID 与发布前临时文件相同，才能证明目标由本次运行创建；哈希只验证内容。实体不同即使内容相同也视为碰撞。清单缺失、损坏、实体身份不可靠或校验失败时停止自动发布与清理，避免凭文件名猜测导致误删。

## 发布与失败边界

文档首行必须是 `# 《中文标题》`，并与登记的语义标题一致。草稿、恢复材料和发布候选留在私有暂存目录；所有门禁通过后，才以保持候选文件实体身份、目标存在即失败的原子 `no-clobber` 操作发布。发生并发占用时使用下一个避碰序号，绝不覆盖既有文件。发布失败时保留暂存目录，最终目录不会出现未登记临时文件。最终文件非空、中文化完成、标题合规、注记覆盖完成、内部标记清零且路径归属验证成功后，才清理暂存目录。若发布后清理失败，保留总结并报告残留的精确路径，不回滚总结或宣称完整成功；残留全部清除后才完成唯一文档交付。

原始本地媒体永不删除。任一阶段失败都不执行成功清理，并报告保留的私有目录。

## 验收

- 59 分钟和恰好 60 分钟不因时长切片；70 分钟得到两个 35 分钟片段；121 分钟得到三个片段。
- Token 预算可以比时长规则产生更多片段。
- 原文被片段覆盖一次，所有片段使用相同前缀。
- 注记编号唯一、递增且完整；只有标记回查的节点被回查。
- 每个注记条目在成稿中恰好覆盖一次；最终稿无注记编号、无时间戳、无处理日志。
- 最终文件名来自实际内容，采用 `中文标题.summary.md`，不含随机来源 ID。
- 非中文来源最终只交付忠实、自然的中文版。
- 完整成功时本次运行只新增一个 `*.summary.md` 并删除自己的暂存材料；既有文件保持不变，失败目录保留恢复材料，用户原始媒体不受影响。
