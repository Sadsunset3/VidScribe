# 博客重构工作流设计

## 目标

VidScribe 将口语化、冗长的视频或播客转录重构为一篇逻辑清晰、自然易读、可公开发布或复习的 Markdown 博客。成功交付只保留最终 `*.blog.md`，但失败时保留私有暂存目录，以便恢复且不误删用户输入。

## 架构边界

Python CLI 继续负责媒体探测、音频准备、Paraformer 转录、三类转录工件持久化和运行创建媒体的安全清理。它不调用通用大模型。

Agent Skill 把 CLI 输出放入 `.video-to-blog-stage-<随机值>`，完成分片、知识提取、博客重构、覆盖检查和原子发布。最终博客验证成功后，才清理该暂存目录中的转录和重构中间产物。

## Token 成本模型

旧式两遍工作流至少需要一次全文提取和一次全文回查，输入成本接近 `2T + 输出`。默认 `economy` 模式把成本调整为：

```text
一次全文提取 T + 压缩证据胶囊 C + 少量定向回查 R + 输出
```

`C` 只保留写作必要信息，`R` 只覆盖有明确风险的节点。固定片段前缀保持一致，并允许底层模型利用提示词缓存。

Token 数优先由当前模型的 tokenizer 计算；没有 tokenizer 时采用保守估算。单片预算最多使用可用上下文的三分之一，为指令、压缩记录和输出预留空间。

## 双重切片

```text
时长分片数 = ceil(duration_seconds / 3600)
Token 分片数 = ceil(estimated_tokens / token_budget)
最终分片数 = max(1, 时长分片数, Token 分片数)
```

70 分钟得到两个 35 分钟片段；密度很高但不足一小时的文本仍可能因 Token 预算增加片数。片段按时间或文本比例生硬等分，不重叠且覆盖原文一次。

## 单次提取

每片只完整阅读一次，并按原始顺序生成：

- 一句话知识锚点；
- 类型和全局递增编号；
- 最小证据胶囊；
- 片段与段落位置；
- 是否需要回查。

胶囊保留必要的参数、因果、步骤、限制和案例背景，不输出空字段。跨片合并只删除证据也相同的真正重复项。

## 按需回查与写作

只有专有名词或参数缺失、步骤断裂、冲突、案例背景不足、低置信度或高风险信息才回查来源附近的最小范围。正常情况下不得再次输入完整转录。

博客以压缩材料为写作输入，结构服从内容。临时锚点标记用于验证每个知识点都被覆盖且步骤顺序正确，发布前全部移除。最后的文风检查只读取成稿。

## 发布与失败边界

文章首行必须是 `# 《名称》` 或 `# 《名称 第X集/期》`。目标重名时使用 `-2`、`-3`，不覆盖已有文件。最终文件非空、标题合规、锚点完整、内部标记清零且路径归属验证成功后，才原子发布并删除本次暂存目录。

原始本地媒体永不删除。任一阶段失败都不执行成功清理，并报告保留的私有目录。

## 验收

- 59 分钟和恰好 60 分钟不因时长切片；70 分钟得到两个 35 分钟片段；121 分钟得到三个片段。
- Token 预算可以比时长规则产生更多片段。
- 原文被片段覆盖一次，所有片段使用相同前缀。
- 锚点唯一、递增且完整；只有标记节点回查。
- 每个锚点在成稿中恰好覆盖一次，最终没有锚点或时间戳。
- 成功目录只保留 `*.blog.md`，失败目录保留恢复材料，用户原始媒体不受影响。
