## Purpose

定义如何把课程元数据与带时间戳转录重构为遵循原始教学顺序的 Markdown 笔记，并约束时间戳、AI 补充、输出质量和失败恢复行为。

## ADDED Requirements

### Requirement: 默认技术课程生成服务
系统 SHALL 默认使用 `qwen3.8-flash`，通过可配置的 OpenAI 兼容 LLM 接口生成 Markdown，并 SHALL 使用非思考或低推理强度配置。

#### Scenario: 配置和输入有效
- **WHEN** 任务已有标准化转录且 LLM 配置通过校验
- **THEN** 系统向配置的模型提交技术课程笔记请求并保存模型原始响应

### Requirement: 保持教学脉络
生成的笔记 MUST 基本遵循转录的时间顺序，并 SHALL 优先呈现问题提出、知识铺垫、理解转折、案例解释、常见误区和最终理解模型，而不是输出无顺序的知识点摘要。

#### Scenario: 转录包含问题和纠偏过程
- **WHEN** 老师先提出问题、展示错误直觉并在后续完成纠偏
- **THEN** 笔记按该推进顺序记录问题、错误理解和纠偏结果

### Requirement: 可核对的时间戳
系统 SHALL 在重要教学节点使用 `[回看 HH:MM:SS]` 格式标记来自转录的时间位置。

#### Scenario: 生成重要节点
- **WHEN** 模型在笔记中记录一个关键转折或易错点
- **THEN** 该节点包含可映射到某个转录句段开始时间的回看时间戳

### Requirement: 限制虚构并区分 AI 补充
系统 MUST 指示模型不得虚构老师展示过的代码、数据、操作或结论；任何必要背景补充 MUST 与课堂记录明确分隔。

#### Scenario: 补充背景知识
- **WHEN** 理解课堂内容需要转录中未完整解释的背景知识
- **THEN** 笔记将补充内容放入明确标记的 AI 补充区域，不冒充老师原话或课堂演示

### Requirement: 生成失败不重复转写
系统 SHALL 在 LLM 失败、输出为空或输入超过配置预算时保留转录，并 SHALL 允许用户只重新生成笔记。

#### Scenario: LLM 请求失败
- **WHEN** 转录已经保存但 LLM 请求失败
- **THEN** 任务展示可重试的笔记生成错误，重试不上传音频且不调用 ASR

#### Scenario: 输入超过预算
- **WHEN** 转录与 Prompt 的估算输入超过当前配置的上下文预算
- **THEN** 系统在调用 LLM 前停止并提示首版不支持分块生成
